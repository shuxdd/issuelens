# 10: 让每次调查可追踪、可计算成本

**What to build:** 让项目作者和贡献者能够追踪一次调查经历的状态、检索、工具、模型调用、Token、费用、延迟和停止原因，并能在 Langfuse 不可用时保留本地记录。

**Blocked by:** 08: 贯通完整 Agent 的 supported 调查路径

**Status:** resolved

- [x] 每次调查产生有顺序、可关联的本地结构化事件。
- [x] 事件覆盖状态转换、检索候选、工具参数摘要、模型调用、耗时、Token、费用和终态。
- [x] Langfuse 能显示同一调查的节点、工具和模型调用层级。
- [x] 评测分数可以关联到相应调查轨迹和实验运行。
- [x] 关闭 Langfuse 后，调查和离线评测仍能完成。
- [x] 上传观测数据前排除 API 密钥、环境变量和不必要的容器原始输出。
- [x] 固定测试能验证异步调查不会丢失父子事件关系。

## 答案

在公共 `run_investigation` 接缝上复用工单 09 的事件与运行结果，增加稳定的
run/trace/event 标识、顺序和 UTC 时间、显式父子关系、检索摘要、模型调用及
Token/费用/延迟聚合。四类既有终态保持不变，结构化输出重试中的模型用量也计入统计。

新增单一可选 Langfuse 出口：关闭时不导入或初始化 SDK；启用时将调查、状态、工具和模型
映射为 trace/span 层级，并允许报告完成后把固定评分关联到 trace 与 experiment run。
初始化、发送和刷新失败只追加不含错误正文的本地降级事件。出口仅上传白名单摘要并统一清洗
凭据和 Bearer 值，不上传完整环境、提示词、工具结果或容器原始输出。

逐项红—绿覆盖稳定标识与顺序、父子关系、模型统计、完全关闭、固定 Langfuse 层级、
三阶段失败降级、统一清洗、评分关联、状态/检索摘要、重试聚合、异步隔离和工单 09 回归；
最终审查另发现根观测带伪父 span，定向测试先失败后以移除伪父标识转绿。

离线验收：调查定向与工单 08–09 回归 69 passed；后端全量 182 passed，Ruff、mypy、
检索回归、固定调查两次字节一致回放、前端 Vitest/ESLint/TypeScript/Vite build、
`docker compose config`、全新 Compose 构建及 8 条 HTTP 冒烟均通过。`pnpm check` 在项目
脚本前仍因 `[ERR_PNPM_IGNORED_BUILDS]` 失败，按约定直接运行四项前端检查并通过。首次
Docker Hub TLS 握手超时，重试后成功。Compose 已停止，PostgreSQL 数据卷保留。

固定客户端验证后，项目作者又在本地自托管 Langfuse 中运行固定调查，并确认 Traces 界面
能够正常查看调查、状态、工具和模型调用层级，最后一项外部验收通过。PRD 和 CONTEXT 无需
同步：产品约束与领域术语未改变；README 已补充本地事件和可选出口的运行说明。
